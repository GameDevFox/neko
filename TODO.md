- [ ] **`.claude/rules/` with `paths:` frontmatter — the on-demand mechanism that `@` imports and skills both fail to provide.** A markdown file in `.claude/rules/` whose YAML frontmatter says `paths: ["**/*.{ts,tsx}"]` loads **only when Claude reads a matching file**: deterministic on the file read, rather than eagerly like an `@` import (the docs are explicit — *"splitting into @path imports helps organization but doesn't reduce context, since imported files load at launch"*) or on the model's judgment like a skill. It works at user level in `~/.claude/rules/`, which is what makes it interesting here. **First application: the JS/TS Code Style block in the global `~/.claude/CLAUDE.md`** — 13 lines (arrow functions, no `class`/`this`/`new`, named constants, semicolons) that are dead weight in the Python repos (Chatterbox-TTS-Server, ComfyUI, whisper-server, hermes-agent) and the writing ones (wheat-fields, japanese). `~/.claude/rules/typescript.md` with a `paths` glob fires exactly when it should and costs nothing the rest of the time — and it beats a skill for this specific case, because a skill's trigger is "about to write TypeScript", which is too late if it misfires, where a path rule fires on the read. **Caveat: a rule with no `paths` field loads unconditionally at launch, same as CLAUDE.md** — the frontmatter is the entire point. Other candidates: any per-language style; anything in a project CLAUDE.md that only applies to one directory. From the same docs page and worth knowing: `claudeMdExcludes` skips other teams' CLAUDE.md files in a monorepo; block-level HTML comments in a CLAUDE.md are stripped before injection, so maintainer notes are free; `/doctor` proposes trims for a checked-in CLAUDE.md; and nested CLAUDE.md files in subdirectories already load on demand (kitsune's `packages/*/CLAUDE.md` are fine as-is, though domus at 424 lines and system at 353 are over the 200-line target).
